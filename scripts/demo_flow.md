# MemoryLens — Demo Walkthrough Script

> **Audience**: Recruiters, judges, and developers seeing MemoryLens for the first time.  
> **Duration**: ~8–12 minutes  
> **Goal**: Demonstrate that MemoryLens is a *personal memory graph*, not just a screenshot search app.

---

## Pre-Demo Checklist

Before starting the demo, ensure the following is ready:

- [ ] Backend running: `cd backend && uvicorn app.main:app --reload`
- [ ] Frontend running: `npm run dev` (opens at http://localhost:5173)
- [ ] Demo data seeded: `cd backend && python ../scripts/seed_demo.py`
- [ ] Browser at http://localhost:5173 — full-screen, dark mode
- [ ] Two terminal windows open (backend logs visible in one)

## Troubleshooting During Demo

| Problem | Quick Fix |
|---------|-----------|
| No memories showing | Run `python scripts/seed_demo.py` |
| Search returns 0 results | Check backend is running on port 8000 |
| Knowledge graph empty | Open Connections → wait 3s for graph to load |
| Chat gives generic answer | Verify GROQ_API_KEY is set in `backend/.env` |
| Related screenshots missing | Check relationships were seeded (look for "Relationships: XX" in seed output) |

## Talking Points for Q&A

**"How does it extract information from screenshots?"**
> It sends each screenshot to a vision LLM (Groq's Llama 3.2 vision model) which extracts title, summary, entities, app name, domain, tags, and confidence. The OCR text is also extracted and stored.

**"How does search work?"**
> Hybrid search: 60% pgvector cosine similarity (768-dim embeddings from SentenceTransformers) + 40% PostgreSQL full-text ranking. Sub-millisecond at scale with HNSW index.

**"How are relationships computed?"**
> Four scoring functions: semantic (embedding cosine > 0.65), temporal (within 2-hour window), domain (same website), shared entity (same named entity). Only top-50 candidates are compared per memory — not O(n²).

**"What about privacy?"**
> Everything runs locally — SentenceTransformers embeddings, PostgreSQL database, FastAPI server. No data leaves your machine unless you configure a cloud LLM provider.

**"How does it scale?"**
> pgvector HNSW index handles 100K+ vectors. The relationship engine uses candidate pre-selection (entity overlap → temporal bounds → ANN top-K) instead of all-pairs comparison.
